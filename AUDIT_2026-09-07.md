## Defects fixed in this audit

1. **Switching stores with unsaved editor changes.** The store selector changed the active store before asking about unsaved changes. A subsequent save could use the wrong store context. Switching now asks first, saves against the original store, and preserves changes when the customer stays or saving fails. Store-specific detail routes return to their parent list when changing stores.
2. **Invalid manual-order quantities and money.** Draft orders silently rounded fractional quantities and accepted invalid discount/shipping values. Creation now rejects fractional or unsafe quantities, negative/non-integer/unsafe money, and discounts exceeding the subtotal before inserting records.
3. **Inactive products in saved manual drafts.** A product could be disabled after saving a draft and still be converted into an order. Conversion now rechecks that each product is active, without changing stock on rejection.
4. **Legacy order subtotals.** Two existing orders had a zero subtotal despite matching positive item totals. An idempotent migration backfills only rows whose items, discount and shipping exactly explain the stored charged total. Ambiguous rows are not guessed or changed.
5. **Inaccessible review-rating names.** Each radio button now has a distinct accessible label from “1 star” to “5 stars”. The existing silent close-after-success review flow remains intact.
6. **Cross-store cookie consent.** Stores on the same hostname shared one consent storage key. Consent is now scoped by store; a decision for one store no longer silently accepts another store's tracking.
7. **Analytics settings not enforced consistently.** Visitor/tracking endpoints now respect disabled analytics and required analytics consent. Explicit rejection is carried through checkout and OTP tracking requests. Rejection does not stop checkout or order creation. Browser marketing tracking also respects explicit rejection, even when opt-in is optional.
8. **Broken built-in privacy-policy links in the cookie banner.** The banner resolves the built-in link to the current store's published privacy policy, and omits that link when the policy is absent or unpublished. Custom policy links are preserved. No policy text was invented or published.

## Browser evidence

- Main ten merchant routes were loaded and checked on desktop, and at measured CSS widths of **390 px and 319 px**. No horizontal document overflow was found in those checks.
- Eighteen additional detail/submodule routes were loaded at 319 px: seven product-operation routes; six settings routes; Online Store Pages, Preferences and editor; product-page editor; order detail. No load error or horizontal document overflow was found.
- A disposable customer placed a COD order, accepted a post-purchase add-on, reached the Thank You page with two line items and the correct total, and refreshed the saved order successfully.
- A disposable product review was submitted, closed without an approval message, approved in the merchant workspace and shown publicly.
- Store switching was reproduced before the fix and rechecked after it: Save and Leave saved the original store, then opened the other store without carrying over the old detail ID.
- The final served review form exposes individually named rating controls. The cookie reject button dismissed its banner; server-side consent and checkout behavior are also regression-tested.

These are Chrome viewport checks, not real-device, Safari or Firefox certification. An extension messaging warning was observed without an application stack; it was not classified as an application failure.

## External and capability limits

- **PostgreSQL:** the current local app uses SQLite. PostgreSQL authentication, migrations and production behavior were not live-validated.
- **OTP:** tests use mocks. A real trial-provider delivery still depends on valid configuration and a verified recipient; no SMS was sent in this audit.
- **Payment:** the current checkout supports COD. Unsupported prepaid methods are rejected; no live gateway payment or refund was attempted.
- **Domain/SSL, delivery partners, external sales channels and pixel destinations:** local adapter tests do not establish that a particular live account, DNS zone, certificate issuer or provider is connected correctly. Those require a separately scoped live test.
- **AI-assisted page generation:** existing local generation/import tests were exercised; no paid external generation request was made.
- **Gift-card checkout redemption and Shopify-style theme importing:** these are not delivered capabilities merely because their related management screens exist.
- No production deployment, external marketing event, live carrier shipment, real payment or real customer communication was performed.

The local app is verified within this scope. Do not interpret this report as unconditional production readiness.

## Reproducing the checks

From this workspace:

```powershell
npm run check
npm audit --omit=dev
node scripts/audit-local-data.mjs
```

For the disposable browser/API fixture, run `node scripts/audit-server.js` in a separate terminal. It uses in-memory databases on loopback ports 4188 and 4209; OTP/pixel calls are blocked and pincode lookup is fixture-only. Then run `node scripts/commercial-qa.mjs http://127.0.0.1:4209` once against the fresh fixture. The commercial script emits disposable account credentials; do not reuse them for real accounts. Restart the fixture for another fresh run. Stopping it discards its temporary records.

New regression files: `test/audit-navigation.test.js`, `test/audit-commerce.test.js`, `test/audit-privacy.test.js`; updated review regression: `test/review-submission-ui.test.js`.
